## Product findings for Radu

Fixed on this branch, needing release review:

1. **Claude Code headless capture.** `claude -p` exits before an `async: true` Stop hook
   finishes its POST, so headless and CI sessions lost every assistant turn. Fix: synchronous
   Stop hook within the existing 30 s timeout, plus migration of installed async hooks.
   Trade-off: interactive users now wait for the capture POST after each reply, up to 30 s on a
   cold shim. The original shim commit said "Stop stays async" on purpose.
2. **NanoClaw stored user text.** The runner wraps user text in an XML envelope and escapes
   entities; captures stored the envelope. Fix: decode one recognised envelope layer in capture
   and legacy opener recovery. Memories written by NanoClaw change shape.
3. **OpenCode capture at exit.** The plugin's capture POST was fire-and-forget and died when
   the CLI exited; the harness caught a missing assistant row in the plugin-only case. Fix:
   track pending work and drain it in the plugin `dispose` hook, bounded at 30 s.
4. **Memory-first ordering.** Claude read a local file before recalling in the continuity
   scenario. Fix: rules text now says recall from MidBrain before local files and keep complete
   IDs in one query. Every client's managed rules block is rewritten on next startup.

Open, not fixed:

5. **Codex silently skips untrusted hooks in `exec`.** No warning in `--json` output. A fresh
   install captures nothing until a human runs `/hooks`. Trust is keyed on the hook command
   string, so any release that changes that string silently disables capture for every Codex
   user until they re-approve. No cross-version identity check exists yet.
6. **Codex `exec` approval policy `never` auto-denies MCP tool calls.** Headless Codex users
   get no recall. The harness bypasses approvals; real users cannot without the dangerous flag.
7. **Installer self-heal cannot be tested.** `install.mjs` fetches a hard-coded npmjs URL and
   accepts stable versions only, so the built-in update path never runs against the loopback
   registry or an rc.
8. **NanoClaw formatting retries.** The runner sometimes asks the model to resend a reply in
   its delivery wrapper, producing two native assistant replies per message, both captured as
   memory. Documented as an exception; arguably a NanoClaw bug.
9. **Codex one-off marker loss.** In the first required run Codex's assistant capture lost the
   literal marker once. Two focused reruns did not reproduce it. Unexplained; the harness has
   zero retries by design.
10. **No uninstall path** in the product, so uninstall idempotency is untestable.

### New product finding: NanoClaw retry prompts become user memories

Every time the NanoClaw runner rejects an unwrapped reply it injects a user-role message:

    <system>Your response was not delivered — it was not wrapped in <message to="name">...</message>
    blocks. All output must be wrapped … Please re-send your response with the correct wrapping.</system>

MidBrain's user hook stores that text as a 300-character user memory. Seen in the transcript
and as `STORE: role=user textLen=300` in every group log where a retry happened. The envelope
decoder added in `5b1f1fe` only recognises `<context/><message>` wrappers, so this passes
through. Fix: drop or tag `<system>` envelopes in NanoClaw user capture. Together with the
double assistant reply this means one retried turn writes three junk rows.
